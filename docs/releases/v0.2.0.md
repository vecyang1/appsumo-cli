# v0.2.0 — public catalog, Q&A, and account portfolio

Published 2026-08-14 at
<https://github.com/vecyang1/appsumo-cli/releases/tag/v0.2.0>.
This file is the source; the GitHub release body is published from it.

Three new read-only surfaces, and several fixes for cases where the CLI could have reported a confident wrong answer.

Everything here is read-only. Nothing in this release refunds, transfers, activates, changes plans, checks out, or mutates account data.

## Install

```bash
go install github.com/vecyang1/appsumo-cli/cmd/appsumo@v0.2.0
```

Requires Go 1.26.6 or newer. `go install` writes to `$(go env GOPATH)/bin`; if `appsumo` then reports `command not found`, that directory is not on your `PATH`.

## New

**`appsumo deals list|sync|diff`** — the public deal catalog. `sync` records a timestamped snapshot; `diff` reports what moved between the two most recent ones: arrivals, departures, price changes, stock movement, and countdown timers appearing.

```
changed  alumni-bundle   codes_remaining 1125 -> 1124
changed  viloud          codes_remaining 3754 -> 3751
```

**`appsumo questions <product-slug>`** — every public question thread for a product, with answers nested underneath.

**`appsumo portfolio`** — an account rollup: status, redemption, licensing, and refund window, with the products that actually need action listed separately.

**`--save`** on `reviews` and `questions` stores flattened comment threads in SQLite, so `appsumo sql` can join them against the products you own.

All three public surfaces work with no credentials configured, and never read or send the session cookie.

## Three things the API says that are not true

Each was measured against the live API on 2026-08-14, and each fails silently — HTTP 200, a healthy-looking response, and a wrong answer.

**The catalog loses 16% of itself without a `sort` parameter.** Walking `page` alone to exhaustion returned **305 of 363** declared deals with 58 duplicates. Adding `sort=newest` returned 363. The sort *value* is ignored — `newest` and `price` give the identical set in the identical order — so the obvious test of changing the value says the parameter is decorative, while removing it silently drops rows. The CLI always sends one, and reconciles every walk against the catalog's own declared total.

**`is_redeemed` is `false` on every product**, including all 36 activated on a live 70-product account. A rollup keyed on it presents an action list of 70 items that do not exist. `portfolio` derives redemption from `redeem_date`, and reports the disagreement rather than quietly picking a side.

**`codes_remaining: 0` never means sold out.** 152 of 363 deals report it, and every one of them has `uses_codes: false`; no deal that actually sells codes reports 0. `percent_claimed` is `-1` on all 363. Both are reported as unknown, never rendered as a number.

## Fixed

- An early stop triggered by a detected anomaly no longer certifies itself complete. Only `--limit` and the request cap set that flag before, so a walk that stopped *because the source was re-serving windows* could still report success whenever its count happened to match — and `deals sync` reads exactly that verdict to decide whether to persist a snapshot.
- Public commands no longer claim your session may be unauthenticated. That diagnosis came from shared code, so `deals`, `reviews`, and `questions` — which never authenticate — printed it verbatim, while the account commands that genuinely needed a remedy were given none. Account errors now name `APPSUMO_COOKIE` and `--cookie-file`, and distinguish "no cookie configured" from "the configured cookie was rejected".
- Unreadable licensing flags are counted and warned about rather than folded into a headline count as `false`.
- Reports echo the parameters a crawl actually sent, not the ones requested.
- An empty `warnings` array serialises as `[]` rather than `null`.
- Two catalog syncs inside the same second no longer collapse into one snapshot.
- `appsumo sql` accepts a multi-line `SELECT`.

## Security

- **Go floor raised to 1.26.6.** go1.26.3 carries seven standard-library vulnerabilities reachable from this CLI — `GO-2026-6218`, `GO-2026-6090`, `GO-2026-5972`, `GO-2026-5856`, `GO-2026-5039`, `GO-2026-5037`, `GO-2026-5026` — across `net/url`, `crypto/tls`, `encoding/asn1`, `net/textproto`, `crypto/x509`, and `net/http`. CI installs the exact version in the `go` directive, so that directive is the floor that matters.
- The macOS cookie-decryption reference now uses a placeholder instead of a worked example. The 0.1.0 release commit had documented `security find-generic-password -s "Chrome Safe Storage"` with its real output — a key that decrypts every cookie in that machine's Chrome profile. It was caught before the commit was ever pushed, so nothing leaked, and a test now scans every tracked Markdown file for credential-shaped example values. Documentation prose is the one place the cookie and redaction rules do not look.

## Verification

`go test`, `go test -race`, `go vet`, `staticcheck`, `govulncheck`, and an install smoke that installs the binary and runs it from outside the checkout — all green in CI on the tagged commit.

Beyond that, each guard was mutation-tested: broken deliberately to confirm it fails. One initially could not go red at all — probed with a randomly generated key it passed, because roughly one 16-byte key in twenty contains no digit — and is now pinned with fixed vectors.

Live, through the installed binary: 363/363 deals, 351/351 questions on growify, 224/224 reviews on growify and 917/917 on tidycal, and a 70-product portfolio.
